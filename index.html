⊞ Problem Definition & Applications
What is Vertex Cover?

Input: Undirected graph G = (V, E) and integer k (0 ≤ k ≤ |V|)

Question: Does there exist a subset C ⊆ V with |C| ≤ k such that every edge in E has at least one endpoint in C?

Example: Triangle (3 vertices, 3 edges) — YES for k=2 with C={a,b}; NO for k=1 (any single vertex leaves one edge uncovered).

Real-World Uses:

• Network monitoring: place monitors so every link is watched

• Bioinformatics: identify critical genes covering all interactions

• VLSI: circuit fault detection

Why is it Hard?

NP-Complete: Checking a proposed solution takes O(m) time, but finding the minimum cover requires (in the worst case) exponential search over all subsets.

Implication: No polynomial-time exact algorithm is known (unless P = NP).

Response: Use a 2-approximation — greedy finds a cover guaranteed to be at most twice the optimal in O(m²) time.

NP-hardness applies to general graphs only. Bipartite graphs are solvable in polynomial time via König's theorem: minimum vertex cover = maximum matching.

⊞ NP-Completeness Proof (3-SAT Reduction)
Step 1: Vertex Cover ∈ NP

Certificate: A proposed cover C ⊆ V (stored as a boolean array, size O(n))

Verifier (O(m)):

  1. Check |C| ≤ k → O(1)

  2. For each edge {u,v} ∈ E: check u ∈ C or v ∈ C → O(1) per edge, O(m) total

✓ Polynomial verification → Vertex Cover ∈ NP

Step 2: NP-Hard via 3-SAT Reduction

Goal: Given any 3-SAT formula φ with n variables and m clauses, construct a graph G and integer k such that φ is satisfiable ⟺ G has a vertex cover of size k.

Variable gadget: For each variable xᵢ, create an edge between vertex xᵢ and vertex ¬xᵢ. Any cover must pick exactly one — encoding the truth value.

Clause gadget: For each clause (ℓ₁ ∨ ℓ₂ ∨ ℓ₃), create a triangle on three vertices. Connect each triangle vertex to its matching variable vertex. Any cover needs ≥ 2 triangle vertices.

Gadget counts: 2n + 3m vertices · n + 6m edges · k = n + 2m

Forward (→): Satisfying assignment A → pick the true literal from each variable gadget (n vertices) + the 2 non-satisfying clause vertices from each triangle (2m vertices) = n + 2m = k. ✓

Backward (←): Cover C of size k = n + 2m forces exactly 1 from each variable gadget (defines assignment A) and exactly 2 from each clause triangle (the excluded vertex ℓ is outside C; its connection edge forces its variable vertex into C; that variable vertex is in C iff the literal is true → every clause satisfied). ✓

Why exactly 2 per triangle? Not 1: one vertex covers only 2 of 3 triangle edges — the third is uncovered. Not 3: budget k = n + 2m is exact — taking 3 from any clause exceeds it.

Reduction time: O(n + m) — linear in input size. ✓

⊞ Brute-Force Strategy

Approach: Try all subsets in size order (0 → k). Stop at first valid — guaranteed minimum.

Quality: Exact optimal (|C*|)

Time: O(C(n,k) · m) ⊆ O(2ⁿ · m)

Space: O(n)

⚠ Exponential — impractical for n > 20

⊞ Greedy 2-Approximation Strategy

Approach: Pick any uncovered edge, add BOTH endpoints, remove all incident edges. Repeat.

Quality: |C| ≤ 2·|C*| — proved via matching lower bound

Time: O(m²) naive implementation

Space: O(n + m)

✓ Polynomial — practical for large graphs

⊞ Complexity Summary

Brute-Force:

Iterate subsets by size (0→k), check all m edges per subset.

Worst case: O(C(n,k)·m) ⊆ O(2ⁿ·m). Space: O(n).

Greedy 2-Approximation:

At most m iterations (one edge picked per step). Each iteration scans remaining edges: O(m) per step.

Total: O(m²). Space: O(n+m).

Greedy: polynomial. Brute force: exponential. The chart makes this concrete.
